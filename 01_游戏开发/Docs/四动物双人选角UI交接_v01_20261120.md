## 统一视觉与布局

沿用宣纸底、手绘墨线、朱红细框、青绿与朱红交互色。角色保留各自动物轮廓、服装、性格与动作，增加纸纤维、折叠体块和贴纸切边，使立体预览与纸艺页面自然融合。颜色保持活力，不能整体灰化，也不改成写实毛绒材质。

总览采用四扇屏风式横向展示，四个模型预览都在各自的选择按钮上方。详情放大当前角色，模型正下方保留单一“选择角色”按钮，旁边展示简短角色介绍与原有技能。五页统一字体层级、边框、纸张、按钮、图标与底部状态栏。

P1 使用青绿圆标与“P1”文字，P2 使用朱红菱标与“P2”文字；另显示“未选择／已选／已准备”等状态文字。不能只靠颜色区别玩家。每页持续显示双方状态；详情同时写明当前由哪位玩家浏览，避免一个大按钮的操作归属不清。

## 双人选择规则

每位玩家分别保存 `focusedId`（浏览）、`selectedId`（已选占用）与 `ready`（准备）。浏览不改变已有选择；可以查看搭档已选角色的详情，但不能选成同一个角色。冲突时只拒绝当前操作，并提示由谁占用，绝不替搭档换角或取消其准备。

P1 沿用 A／D 浏览、F 确认或取消；P2 沿用左／右方向键浏览、主键盘斜杠确认或取消。未准备时，按确认或点击归属明确的“选择角色”按钮，都原子完成“选中并准备”。已准备时再次确认仅取消自己的准备，保留已选；随后才可改选。没有“点选择后还必须再点一次准备”的额外流程。详情大按钮始终标清作用玩家；搭档“已准备”标记只展示状态，不能点它取消搭档的准备。

详情返回总览保留双方已选与准备。Esc 逐级返回：详情 → 总览 → 地图。键盘操作始终作用于输入所属玩家，不因当前详情属于另一人而错误接管其选择。

已准备玩家可以查看另一角色详情；若该玩家拥有当前详情页，取消准备时保留原 `selectedId`，同时将 `focusedId` 同步为当前详情角色。这样下一次 F／斜杠与页面选择按钮始终指向同一候选。

只有两人各选一个不同角色且均已准备，才启用“进入工坊”。进入时原子设置 `transitionPending=true` 并捕获不可变的双方角色 ID 与组合键快照，只提交一次加载。等待期间拒绝浏览、选择、取消准备、详情、返回和重复进入，避免加载发起后阵容变化；失败则清除等待状态、保留原选择与准备并恢复操作，成功只将捕获的快照移交关卡。上述为待实现接口与验收要求。

选角阶段不产生收藏解锁，组合交子继续由两人的排序角色 ID 组合键绑定，按既有交付规则记录。

## 静态状态示例与动态绑定

本批实际图示例为：总览中 P1 泡泡“已选／未准备”，P2 墨墩“已选／已准备”。P1 状态可由取消准备后保留已选产生。四张详情由 P1 分别浏览对应角色、尚未确认；P2 在泡泡、递蕉、烘栗详情中为墨墩已准备，在墨墩详情中为泡泡已准备。详情候选不自动代表已占用，实际 `selectedId` 必须独立读取。上述状态及每张文件规格已记录到状态合同 `visual_examples`。

本批图不包含双方均已准备后的可进入示例。正式游戏必须根据同一状态快照动态绑定模型归属、按钮文案、双人状态和进入按钮可用性，不能把图上的角色名、准备状态或禁用态写死。截图中的 3D 效果、状态、提示均为美术示例，不作为功能已运行的证据。

## 后续工程与验收边界

真实三维预览可使用独立预览对象与 PreviewCamera／RenderTexture，最终以对方 Unity 工程架构为准；应统一机位、光照与视觉尺度，同时保留胖瘦、高矮差异。当前尚缺四动物真实模型、待机姿态或动画、独立头像和 UI 拆件、目标工程材质与渲染适配。

五张整页均已由主代理逐页目视检查：角色预览位于选择按钮上方，P1 圆标／P2 菱标与编号明确，页面纸艺语言一致；泡泡头像及递蕉 P1 角标已另存修正版。交接复核了文件存在、实际尺寸、RGB 格式、角色与旧技能来源、JSON 结构及文档链接。生成图片中的文字仍需在正式 UI 中用可编辑文本重建。

已完成的是图片与交接资料；双方准备后的可进入态、冲突提示、取消准备和实际双人输入尚需工程验证。边界验收须额外覆盖：准备后查看另一角色再取消，按钮与确认键目标保持一致；进入等待期间所有改选与返回均被拒绝，加载失败恢复原选择与准备，成功按捕获快照创建双方角色。工程验收另记真实工程路径、提交版本与实测结果。当前不把本机美术文档或效果图写为已完成的 Unity 功能。
